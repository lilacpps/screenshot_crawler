### N2 native-pixel follow-up (current capture implementation)

**OBSERVED AND IMPLEMENTED:** The first-party normal viewer creates three overlapping segment canvases from a shuffled JPEG tile atlas, calls the original `toDataURL("image/jpeg", 0.9)`, then creates the Blob URLs displayed by the body images. The adapter observes only the top-level Yanmaga viewer route, clones opaque sRGB canvas pixels immediately before that original encode, and calls the original method once with unchanged arguments/return/exception behavior. Pixel copies are associated only through unique exact equality of the resulting JPEG bytes, Blob bytes, and displayed current source. Duplicate or conflicting candidates, over-budget state, source drift, and any unsupported style/layout reject native capture for the whole group.

The verified nested layout is `#content-pN > .pt-img > three clipped segment hosts > one image each`. First-party metadata and the logical `.pt-img` rectangle establish the native 1125×1600 page bounds. The segment images are 1127×536, 1127×536, and 1127×538 at native Y positions 0, 532, and 1064. They overlap four rows, and the last segment extends two rows below the page; the adapter paints in native DOM order and clips at the logical bounds instead of stacking whole segments. The narrowly accepted wrapper profile allows only observed pure X translation and 0/2 CSS px right gutter. Host pseudo-elements must satisfy the measured no-paint style predicate. Full nested geometry/style/source proof is revalidated atomically across the spread before accepting output.

The composed page must be fully opaque. It is encoded as a single-frame lossless WebP (`VP8L`) at 1125×1600; decoding must reproduce the composed RGBA pixels exactly. Metadata records `source_native_bytes_used=false` and `source_native_pixels_used=true`. Any page/group proof or encoder failure uses the existing rendered locator PNG fallback with an explicit reason; there is no partial mixed-method group.

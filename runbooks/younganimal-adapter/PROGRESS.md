## Phase 02 exact-response timeout recovery (2026-10-11)

- The adapter retries only Playwright `goto` `TimeoutError` while waiting for `DOMContentLoaded`, and only when listeners installed for that exact attempt captured exactly one main-frame document navigation request to the expected URL and the matching Request object received exactly one HTTP 200 response for that same URL. `page.url` must equal the expected URL after timeout.
- The adapter checks the existing AccessGuard before deciding, waits 2 seconds, checks the AccessGuard and exact URL again, then makes at most one retry for that navigation. One explicit budget shared across the canonical root and all range routes allows at most two retries for the whole work.
- Unknown status or request/response identity, non-200, redirect or route drift, other Playwright errors, AccessGuard stop, and cancellation do not retry. Request/response listeners are removed in `finally`; the retry path reads no response body or headers.
- The ignored full-run harness counts actual `goto` attempts (cap 34, including retries), range routes (cap 31), and total time (240 seconds). If a timed-out attempt has the positive 200 proof, it may evaluate at most 2 seconds of metadata only: readyState/path, heading/listing/public-root counts, row/unique-ID counts, selected range label, and anchor count. Evaluation errors remain UNKNOWN and never alter retry eligibility.

## Registration and browser use

`HanayumeDiscoveryAdapter` is registered in the CLI Discovery registry. `HanayumeAdapter` is registered in the manual Viewer and Batch adapter registries; `HanayumeSitePolicy` is registered in the Batch policy registry. All paths use the shared Crawler Chrome through the existing CDP `BrowserSession` and Playwright `Page`; none launches Chrome or selects a profile. Discovery writes through the existing `DiscoveryService` and Catalog schema. Batch uses the existing Planner/Executor/Runner/Packager; no site-specific Core branch or Catalog schema was added.

The strict Watchlist episode URL is `https://hanayume.com/episodes/<13-lowercase-hex-id>`. Episode IDs are paired with the observed work ID from the unique `#xHeader a.ep-h-main-h-series` link as `<work-id>:<episode-id>`. This header link is outside the episode-list subtree. The adapter separately requires one `div.series.mode-ep` containing one `.series-eplist-wrap`, one target header link, and the same work identity/title on every range page. Global series links are not used because the page also contains related works.

## Enumeration and ordering

The observed listing declares ten contiguous oldest-first ranges, from `1-30` through `271-296`. The actual page URL must equal the declared route. Live evidence showed the active selected anchor points to the seed episode path on all ten ranges; only that unique selected anchor may use this exact seed alias. Each range must contain its declared number of unique episode IDs. All ranges are buffered before the adapter yields any record, in both full and incremental modes. Missing/duplicate rows, foreign work context, route/range drift, invalid labels, or an AccessGuard stop make Discovery incomplete and prevent Catalog source updates.

## Viewer capture

Manual Viewer capture accepts the exact supported episode URL, checks its unique scoped work link, then reads the exact bare same-work listing and validates its finite numbered-range set. If that listing contains the unique target row, only the exact `無料` label proceeds; an ambiguous, duplicate, or nonfree target fails immediately. If absent, the adapter visits only observed numbered routes, checking the actual route, selected marker/label, unchanged range set, declared row count, and page-local unique IDs, and stops at the first unique exact target row. Only if no target appears does it exhaust the declared ranges. After opening the exact episode again, it rechecks scoped work identity and one exact target row with `無料`. Full-work range coverage/global identity uniqueness remains Discovery responsibility; this is a bounded freshness check, not a replacement.

The reader contract is limited to the observed desktop `mode-spread` layout. Viewer counters and `#xCVPages` wrapper structure are checked together. Wrapper slots 1 through N−5 are only structural body candidates. An active body wrapper is one whose center is inside the viewport; mere intersection does not make a prior offscreen wrapper active. Each selected page becomes ready only when its own active wrapper and canvas have the observed `mode-loaded` and `mode-rendered` markers, the expected `.-cv-page-canvas` parent, positive dimensions, and the selected canvas is fully visible. The observed prior-page wrapper at 3/55 intersected the viewport by 15.33 px while its canvas was offscreen; the center rule excludes that stale slot. The exact offscreen states `mode-loading` alone and `mode-loading mode-req-render` were observed with no canvas and remain non-ready placeholders. Other unknown state classes fail closed. A rendered wrapper requires the loaded marker.

The adapter rewinds through the observed public seek control, then advances by one verified range-input step per spread. It validates counter, active slots, and ready slots across three stable observations before each capture. The current spread's selected canvas pixels are read atomically in one page evaluation and validated as a PNG with dimensions matching that exact canvas. Captured slots must be contiguous, without gaps or repetition. After every body slot has been captured, the observed Home seek reaches the terminal UI; only then does the adapter return END. It never follows the next-episode card. Direct PNG errors and timeouts cannot fall through to generic locator/screenshot capture: both generic target hooks fail closed.

The selected output is the rendered body-canvas PNG. It preserves the selected canvas's pixels and actual dimensions, not the higher-resolution 960×1540 source pixels. Source-native replay had positive pixel equality on one page but was not proven across the required page/source-generation cases. The tested 240×385 JPEG tiles reject the tested MCU-8 DCT permutation method. The implementation therefore uses the clean rendered canvas PNG and documents the fidelity reduction. `viewer.hanayume.com` is included in the relevant-host AccessGuard profile based on observed image responses.

## Batch policy and execution

`HanayumeSitePolicy` permits only an available Catalog source with exact `access_mode=free`, using the ordinary `direct` strategy. It rejects `unknown`, `quota`, `paid`, `owned`, `grant`, and `rental`, even if quota or grant timestamps are populated. It declares no quota resources and no grant-only passes. The fresh Viewer preflight rechecks the current same-work row and exact `無料` badge before capture; a stale Catalog row that now displays `今なら無料` fails before any page capture. Successful runs use the existing manifest, ZIP packaging, and Catalog completion path; failures remain pending without an Artifact.

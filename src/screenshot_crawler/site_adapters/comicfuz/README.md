Discovery requires a canonical public work URL, unchanged work identity, a visible sign-in entry, no visible sign-out entry, and a stable exact join between first-party `#__NEXT_DATA__` chapter IDs/labels and the rendered list. It emits every current row. Exactly one visible row-local `無料` marker means `free`; all other access remains `unknown`. Resource, ticket, charge, medal, purchase, and account-entitlement fields are outside this implementation. Full-list global positions are assigned from the validated native list before any bounded selection.

The manual crawl adapter requires an exact `<work-id>:<chapter-id>` target and first visits the same-work public listing. It buffers and validates that complete listing and requires the target's exact current `無料` row before opening its viewer route. Anonymous sign-in/sign-out markers, exact route, and first-party hydration (`mangaId`, `chapterMainName`, `mangaName`) are rechecked during capture; the main title must match the freshly verified free row, and the reader title must match that main title plus the bound optional native subtitle after whitespace normalization. The validated `mangaName` supplies the work title in output metadata. Manual runs require `COMICFUZ_WORK_URL` in the environment file. The adapter does not open a reader route first to discover access.

The supported reader manifest has a contiguous prefix of ordinary unlinked image descriptors, followed by either one linked `isExtraPage=true` image or exactly three extra images with link-presence sequence `(true, false, true)`, then exactly `googleAds` and `lastPage`. The three-extra shape was observed on work 3140, chapter 81136 (第98話): body indices 0-28, extra indices 29-31, and terminal slots 32-33. Visual inspection identified the extras as an official-X promotion, a volume promotion, and another-work recommendation. Only the ordinary prefix is captured; its work-related introductory/relationship charts are retained. Descriptor indices and dimensions must join exactly to rendered `page_N` identities. The final mixed spread must be fully ready; only its body half is saved. For the three-extra shape only, the following exact extra-only pair becomes `AD` after all body indices have been captured and the final mixed spread has been verified. The normal Runner performs one page turn for this pair; it is never captured. Repeated extra tails time out without further turns. Missing/clipped halves, unsafe pixels, body gaps, changed manifests, other extra/link sequences, and unverified terminal states fail closed. This supports the observed shapes only, not arbitrary `isExtraPage` semantics.

END still requires the entire body prefix to be captured, matching episode identity, and cleared or matching inactive image shells. When the current page image is associated with a ComicFUZ viewer-delivered blob response, the adapter preserves those complete JPEG bytes after verifying JPEG framing and native image dimensions. The live probe also established browser-decoded pixel equality for sampled images. If safe response bytes are unavailable, it reads the current visible `HTMLImageElement` into a PNG canvas at its natural dimensions after rechecking the source and geometry. Both capture paths reject unverified filters, masks, clipping, crop, opacity, blend, rotation, reflection, perspective, individual CSS transforms, or legacy clipping; only none or observed positive axis-aligned transforms are accepted. After common page-role, episode-identity, and visual-safety checks, capture stops only when neither verified source bytes nor safe native-pixel PNG readback is available. No claim is made about the publisher's upstream master/upload bytes. Adapter-created manifests and output metadata exclude blob/signed source URLs; this statement does not extend to generic Core diagnostics behavior.

Viewer image response observation is limited to 16 entries, with a 2-second read deadline and 4 MiB `Content-Length` and post-read caps. Playwright `Response.body()` buffers before returning, so the post-read cap cannot limit memory already allocated by Playwright; the header cap and deadline are the available safeguards. Failed, timed-out, duplicate, END, error, and page-close reads are canceled or cleared. The first-party projection omits signed image URLs, so same-dimension descriptor substitution cannot be independently ruled out through a descriptor-to-blob URL hash comparison; native index, role, title, dimensions, current image binding, and geometry are still checked. The site-local AccessProfile observes the public site, `api.comic-fuz.com`, and the observed image host for existing AccessGuard policy; no charge/resource API is called by the adapter.

The adapter is registered for manual `crawl` and normal Batch. Batch policy selects only Catalog sources with `available=true` and `access_mode=free`, always using `direct`; unknown, quota, paid, owned, and unavailable states are skipped. It exposes no resource or grant-only passes. Manual crawl requires `COMICFUZ_WORK_URL`. Batch reads that value when supplied and otherwise derives the canonical same-work listing URL from the validated composite Catalog identity; a supplied URL must match that work. In either path the adapter validates the listing and exact free row before opening the requested viewer. Normal Catalog planning retains Discovery's global `display_position` as the archive prefix, and standard Batch owns ZIP/Artifact/Completed lifecycle without site-specific Core changes.

The adapter uses the existing shared Playwright page/CDP session and does not launch Chrome or modify shared Core.

## Discovery

Watchlist targets use the strict episode URL `https://hanayume.com/episodes/<13-lowercase-hex-id>`. Discovery reads rows only from the unique public `epList` under the route-specific observed ancestry. Episode pages use `div.ep-main.series-safe-filter-target[data-e2e="pageEpisode"] > div.series.mode-ep` (the child has no `data-e2e`) > `.series-eplist-wrap` > `.series-eplist-main`; canonical work pages use `div.series.mode-series-top.series-safe-filter-target[data-e2e="pageSeries"]` directly above the wrapper. The public root is direct under main; `eli` rows are descendants inside `.series-eplist-default.has-store-item.mode-last`. The observed direct `epListUser` history sibling is not enumerated; overlapping copies must agree on exact labels except when the exact episode has a fully proven authenticated active manual grant. Unknown/nested/duplicate roots and every other conflict fail closed. Full range/count/identity validation, global oldest-first positions, buffering, and latest-first/bounded output remain unchanged.

Only exact row-scoped labels are classification evidence. One exact `無料` maps to `access_mode=free`. One exact `今なら無料` maps to `free` only when the current Discovery attempt verifies the observed account markers on the canonical `/series/<work-id>` route; otherwise it remains `unknown`. Missing/duplicate/other labels remain `unknown` unless an exact natural native `waitAndFree` row for the same work and episode promotes the row to a nominal `quota` candidate. This native type does not authorize entry. A conflicting public/account badge row is accepted only under the exact active-grant proof described below; other conflicts fail closed. Catalog stores only `access_mode`, not the raw label. Auth is attempt-local and never persisted. On an exact route/listing, a missing positive marker set is polled for at most five seconds at 150 ms intervals; deadline means no proof and keeps `今なら無料` unknown. Discovery follows the seed's observed work link, reads auth on the canonical series route, returns to the exact seed, and revalidates work/title/ranges before enumeration.

## Viewer capture

Manual Viewer entry validates the exact episode URL and scoped work link, then checks the canonical same-work series listing, auth, and target row. `無料` remains eligible regardless of auth markers; `今なら無料` requires fresh verified series auth. If the target is absent from the episode page, its episode preview must match the nonempty, unselected fresh bare-series preview by complete ordered ID/label signature or exact reverse; target-present entry continues to require the exact matching row. Unknown branches, history-only target copies, conflicts, duplicates, and preview drift fail closed.

Configured Batch uses only its selected Catalog episode URL and configured work/episode identity. Free candidates and unexpired episode grants stay direct; an eligible quota candidate uses the existing same-Page Work Ticket flow. Manual URL entry retains its own fresh preflight. For an identity-bound Batch candidate, `configure_run` installs a page-local route guard before the initial `goto`. It passes the exact canonical selected episode document, the selected episode's observed Next RSC shape, and requests outside the `/episodes/*` and `/series/*` route families (including API, static, and image content). It aborts known nonselected Next route data requests only when the URL is HTTPS on an allowed host with no userinfo/nondefault port, has exactly one nonempty `_rsc` query key, carries `rsc: 1`, has resource type `fetch` or `other`, uses `GET`, and has no `next-router-prefetch` header or value `1`; the off-target path must match the observed 13-lowercase-hex episode/work ID with an observed numbered range or `old` suffix. These are treated as route-data attempts, not proof of framework prefetch. Unknown, malformed, off-target document, non-GET, or other unrecognized first-party route requests are aborted and latch a fatal state before ticket entry or capture. A response to any off-target episode/work route is separately audited as an escaped response. The adapter records only counts and a fixed reason code, never request query values or full URLs. The guard is not installed for manual entry or Discovery. Viewer readiness, sequential body capture, pixel proof, and END remain unchanged; direct Batch also rejects the observed central charge/login gate before capture and at each CONTENT state.

The observed desktop spread layout uses explicit counter, wrapper, readiness, visibility, and terminal checks. The adapter captures every body slot in order and cannot reach generic locator/UI screenshot fallback. END is accepted only after full body coverage and the observed terminal UI.

## Bounded readiness

On a structurally valid canonical series listing, authentication proof is polled for up to five seconds at 150 ms intervals until the complete positive marker set appears. The route and listing must remain exact throughout; timeout leaves `今なら無料` unknown. Viewer initialization waits up to five seconds for the existing unique current/total counter nodes to contain text. Duplicate nodes fail immediately and malformed values still fail in the strict parser. Synthetic browser tests cover delayed and missing counter/auth states. The auth probe observed markers arriving at 150 ms; the counter-missing probe did not directly measure a delayed transition. The final E2E passed after these bounded readiness checks.

## Capture fidelity

Before its first body capture, initialization now requires one second of unchanged canvas
generation/write counts, wrapper/canvas identities, bitmap dimensions, geometry, viewport and
existing strict readiness metadata, sampled every 100 ms. Changes restart this quiet interval;
failure to settle within five seconds stops initialization. This applies to slot 1 in ordinary
layouts and slots 2/3 after the existing leading-empty intro seek. Later page turns and strict
post-encoding proof are unchanged; a later reset still stops without a capture retry.
Sampling adds no image/pixel readback. If the native observer is unavailable, the existing
rendered-PNG fallback uses a one-second metadata-only quiet wait. The tracking mode and timing
are recorded at `adapter_debug.initial_canvas_settle` in failure diagnostics. No new option is
required. Synthetic browser tests pass late same-pixel reset cases and reject continuous resets;
live reduction in failures has not yet been verified.

R2 captures the observed opaque sRGB/unorm8 960x1540 full-frame canvas at draw time into a bounded immutable copy tied to the exact target and episode. Selection requires target/slot/generation/write proof, safe full-frame state, and exact no-background RGBA replay. Strict single-chunk VP8L WebP method 4 is accepted only after full RGBA round-trip validation; encoder failure returns the same verified native PNG. Native unavailability uses clean rendered-canvas PNG for the whole spread at actual dimensions. In the final E2E all 134 pages were native source-canvas WebP with 134/134 independent exact RGBA matches and zero rendered fallbacks. This is decoded source-canvas fidelity, not original JPEG bytes or tile reconstruction.

### Post-encoding verification diagnostics

Native proof rejection still stops capture without retries or a weaker fallback. The error now
includes `verification=<reason>` for console/metrics correlation. Failure details are written to
`diagnostics/metadata.json` under `adapter_debug.capture.verification`: the first failed gate,
before/after selected-slot canvas dimensions, wrapper/canvas geometry, readiness/visibility,
viewport/seek/counters, wrapper/canvas identity equality, and bitmap generation/write counts.
`encode_elapsed_ms` measures the Python encoding stage; verification `elapsed_ms` measures the
browser interval since proof collection, including transport/decode/encoding time.

A failure-only pixel comparison reports `equal`, `different`, `unreadable`, or `not_compared`.
It compares only the same selected canvas at unchanged bitmap dimensions and stores no pixels.
Generation/write changes remain failures even when pixels are equal. Verification timeouts,
evaluation failures, missing observer/proof, and malformed results have distinct reasons.
No new CLI switch is needed. These diagnostics do not establish the cause of historical failures;
the next live failure is needed to identify the actual gate. Synthetic browser coverage includes
same-pixel redraw, pixel change, bitmap reset, replacement, visibility/position/counter/layout drift,
and persistence through the existing failure diagnostics writer.

## Batch policy and execution

Discovery observes the natural same-Page `GET /api/series/access` response and joins `seriesId` plus `episodeId` exactly. A matching `accessType=waitAndFree` promotes an otherwise unknown row to nominal `quota`; exact free labels remain free, and the native access type never authorizes an entry click. Full and incremental Discovery refresh all rows in the already-buffered validated range set, without additional range requests. Before snapshotting each authenticated range, Discovery waits up to five seconds for the episode-local account root to reach the observed ready state. A manual grant requires fresh authenticated series markers and an exact native `waitAndFree` row with `hasAccess=true` and strict `timeRemainingInSeconds` from 1 to 259200. If that episode appears in the account preview, its row must also show `mode-read` and one `eliRentStat` rental marker; a present row without those markers does not grant access. If the exact episode is absent from the preview, that absence is not negative evidence and the exact native row may establish the grant. Unknown/loading/no-user roots fail Discovery closed. No extra range or API request is made. `access_granted_until` uses request-start plus `remainingSeconds - 1`; matching zero remaining explicitly clears it. Missing or malformed evidence preserves the prior grant. That same exact active-grant proof is the only exception to public/history badge disagreement; every other mismatch fails closed.

`HanayumeSitePolicy` admits available free sources as direct, future-granted quota sources as non-consuming direct, and other available quota sources as one `work_ticket` candidate per work (`quota_limit=1`, commit after observed consumption). `work_ticket` is available to normal and grant-only passes. The local recovery guard is at least 23 hours; longer caller cooldowns are honored. Natural target-local native evidence confirms a successful ticket only when the exact post-click `/api/series/access` row changes from `hasAccess=false` to `true`, has positive bounded remaining time, and the exact authenticated `epListUser` row changes to read/rental state. The adapter then records confirmation time for the 23-hour work cooldown and request-start plus `remainingSeconds - 1` for the episode grant, capped by the policy's 72-hour fallback. Confirmed consumption is preserved through later Viewer, capture, packaging, or interruption failures. A single unique visible/enabled `待つと無料で読む` control is checked under the observed central charge ancestry, including an immediate same-element/actionability recheck after Playwright's trial click. Missing/unknown/login/paid/duplicate/changed control states fail closed; no click is retried. Normal Batch stays on the same episode Page for Viewer capture through END and ZIP. `--grant-only work_ticket` confirms entry and updates state with zero captured pages, no ZIP, and the Item pending. Configured direct Batch rejects the specifically observed central Work Ticket/login action both during initialization and again at each Viewer CONTENT state, before capture; ordinary free direct/anonymous entry remains unchanged. Batch does not navigate to `/series/` or enumerate the work before attempting the selected Catalog episode.

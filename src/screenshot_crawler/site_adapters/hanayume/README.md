## Discovery

Watchlist targets use the strict episode URL `https://hanayume.com/episodes/<13-lowercase-hex-id>`. Discovery reads rows only from the unique public `epList` under the route-specific observed ancestry. Episode pages use `div.ep-main.series-safe-filter-target[data-e2e="pageEpisode"] > div.series.mode-ep` (the child has no `data-e2e`) > `.series-eplist-wrap` > `.series-eplist-main`; canonical work pages use `div.series.mode-series-top.series-safe-filter-target[data-e2e="pageSeries"]` directly above the wrapper. The public root is direct under main; `eli` rows are descendants inside `.series-eplist-default.has-store-item.mode-last`. The observed direct `epListUser` history sibling is not enumerated; overlapping copies must agree on exact labels except when the exact episode has a fully proven authenticated active manual grant. Unknown/nested/duplicate roots and every other conflict fail closed. Full range/count/identity validation, global oldest-first positions, buffering, and latest-first/bounded output remain unchanged.

Only exact row-scoped labels are classification evidence. One exact `無料` maps to `access_mode=free`. One exact `今なら無料` maps to `free` only when the current Discovery attempt verifies the observed account markers on the canonical `/series/<work-id>` route; otherwise it remains `unknown`. Missing/duplicate/other labels remain `unknown` unless an exact natural native `waitAndFree` row for the same work and episode promotes the row to a nominal `quota` candidate. This native type does not authorize entry. A conflicting public/account badge row is accepted only under the exact active-grant proof described below; other conflicts fail closed. Catalog stores only `access_mode`, not the raw label. Auth is attempt-local and never persisted. On an exact route/listing, a missing positive marker set is polled for at most five seconds at 150 ms intervals; deadline means no proof and keeps `今なら無料` unknown. Discovery follows the seed's observed work link, reads auth on the canonical series route, returns to the exact seed, and revalidates work/title/ranges before enumeration.

## Batch policy and execution

Discovery observes the natural same-Page `GET /api/series/access` response and joins `seriesId` plus `episodeId` exactly. A matching `accessType=waitAndFree` promotes an otherwise unknown row to nominal `quota`; exact free labels remain free, and the native access type never authorizes an entry click. Full and incremental Discovery refresh all rows in the already-buffered validated range set, without additional range requests. Before snapshotting each authenticated range, Discovery waits up to five seconds for the episode-local account root to reach the observed ready state. A manual grant requires fresh authenticated series markers and an exact native `waitAndFree` row with `hasAccess=true` and strict `timeRemainingInSeconds` from 1 to 259200. If that episode appears in the account preview, its row must also show `mode-read` and one `eliRentStat` rental marker; a present row without those markers does not grant access. If the exact episode is absent from the preview, that absence is not negative evidence and the exact native row may establish the grant. Unknown/loading/no-user roots fail Discovery closed. No extra range or API request is made. `access_granted_until` uses request-start plus `remainingSeconds - 1`; matching zero remaining explicitly clears it. Missing or malformed evidence preserves the prior grant. That same exact active-grant proof is the only exception to public/history badge disagreement; every other mismatch fails closed.

`HanayumeSitePolicy` admits available free sources as direct, future-granted quota sources as non-consuming direct, and other available quota sources as one `work_ticket` candidate per work (`quota_limit=1`, commit after observed consumption). `work_ticket` is available to normal and grant-only passes. The local recovery guard is at least 23 hours; longer caller cooldowns are honored. Batch ordinarily uses the unique target row in the hydrated target-local `epListUser` preview. The exact account row classes `mode-current mode-store-item-blank` and `mode-current mode-store-item-start` are both recognized as ungranted only when no rental marker exists; this is a target-row state distinction, not grant evidence. Active grants retain their stricter read/rental/native requirements. If both unique, nonempty public and account previews are structurally valid but omit the selected episode, an exact same-page `/api/episodes/<episode-id>` response is required for the ungranted prestate in both the initial and final pre-click snapshots; a series-level false row alone is insufficient. It must match all three observed identity fields (`episode.id`, `episode.series.id`, `episode.access.episodeId`) to the selected Catalog episode and work and provide strictly typed `hasAccess`, `accessType`, and bounded `timeRemainingInSeconds`. Duplicate/malformed rows, another current row, or any present contradiction still fail closed. This API evidence never authorizes the click by itself: the exact unique enabled `待つと無料で読む` control must remain under the observed central charge ancestry, with the same-element/actionability check repeated after Playwright's trial click. A ticket attempt is made at most once. Confirmation requires the exact same-page checkout `POST /api/checkout/rental` to return HTTP 200 plus fresh grant evidence. With both previews absent, confirmation requires a current-episode API transition from `hasAccess=false` to `true`, `accessType=waitAndFree`, and positive bounded remaining time, with all three endpoint IDs matching the selected Catalog episode/work. When the target account-preview row is present, the existing stricter positive series-access response plus exact read/rental-history proof remains supported. A present blank target row contradicts either path. Current and series responses are ordered by request-start and equal-time conflicts fail closed. For absent-preview confirmation, a fresh current-episode 3-ID positive proof remains valid when a later-started series response also confirms active `waitAndFree`; both must report `hasAccess=true` and strictly positive bounded remaining time. The countdown values may differ as time passes, so the grant expiry is the earlier of the two request-start plus `remainingSeconds - 1` expiries. A newer denial, paid/unknown state, invalid remaining value, or differing entitlement state fails closed; a fallback read cannot override that contradiction. If the natural current response is missing or the newest native state still explicitly reports `hasAccess=false`, the same Page may issue at most two exact read-only GETs within one attempt-scoped five-second recovery deadline; the limit and deadline do not reset on exception-path reentry. The adapter records confirmation time for the 23-hour work cooldown and the conservative native grant expiry, capped by the policy's 72-hour fallback. Confirmed consumption is preserved through later Viewer, capture, packaging, or interruption failures. Normal Batch stays on the same episode Page for Viewer capture through END and ZIP. `--grant-only work_ticket` confirms entry and updates state with zero CONTENT page captures, zero ZIP, and the Item pending. Generic UI screenshot diagnostics may still be emitted when a candidate fails. Configured direct Batch rejects the specifically observed central Work Ticket/login action both during initialization and again at each Viewer CONTENT state, before capture; ordinary free direct/anonymous entry remains unchanged. Batch does not navigate to `/series/` or enumerate the work before attempting the selected Catalog episode. The current-API transport and exact three-ID response were verified read-only on an already-granted `49b` episode; the preview-absent post-click path is synthetic-only so far, and no further ticket has been used.
